# Windows 小窗玻璃链路分析

日期：2026-10-30。状态：**Windows 小窗性能问题未解决，用户实测未通过验收。** 原生改动为候选实现，提交用于评审和后续排查，不能据此认定优化完成。

用户约束：不再控制、启动或关闭桌面应用；以用户实际反馈为准。

## 未解决问题（Windows）

- 小窗保持静止、后方播放动态内容时，玻璃背景仍有卡顿和约一两帧延迟。
- 拖动时窗口自身移动顺畅，但玻璃背景仍明显跳动、滞后；当前改动没有解决位置与背景的同步呈现。
- 诊断及原版对照测试中曾出现无响应或崩溃，根因未确定，稳定性仍待排查。
- 此分支保留诊断结论和候选实现。静态检查、单元测试或 CI 构建通过均不代表上述问题已修复。

## 完整路径

```text
桌面/视频 → DWM → DXGI 新帧 → 整屏 GPU 快照 → 捕获通知
→ Flutter 栅格线程取纹理 → 按窗口位置裁剪 → 外部纹理导入
→ ImageFiltered 折射/色散 → Flutter 窗口缓冲 → DWM 合成 → 屏幕

鼠标 → 原生窗口位置更新 ───────────────────────────→ DWM 窗口位置
```

两条路径异步推进。裁剪读到了新位置，不代表最终显示时窗口还在该位置。纹理回调计数也不是屏幕显示帧率。

## 测量记录与边界

下列是先前诊断时的短时样本。桌面、视频和后台负载未严格固定，不能把样本间 CPU 差额全部归因于单一改动。CPU 百分比以一个逻辑核心为 100%。

| 环节 | 已取得的证据 | 解释边界 |
| --- | --- | --- |
| 原版捕获/读回 | 约 60 次纹理交付/秒，Map 平均约 0.7 ms/帧；捕获与纹理线程各约 10%–11% CPU | 读回有成本，但不能单独解释全部卡顿 |
| 高频定时轮询 | 曾出现桌面约 144 次更新/秒、有效取得约 100 次/秒 | 提高请求频率不保证稳定交付 |
| 事件驱动捕获 | 一段样本中取得约 144 个桌面帧/秒，纹理回调约 130 次/秒 | 改善源端取得，未测得最终显示节奏 |
| 裁剪与移动 | 较早样本 GPU 裁剪回调中位小于 1 ms；移动事件到裁剪完成中位约 5.3 ms | 不含后续导入、绘制及呈现时间 |
| GPU 共享纹理创建 | 高负载区间回调约 3–4 ms/次，大部分计时落在 CreateTexture2D | 候选逐帧创建资源的成本明显且随负载变化 |
| 滤镜旁路 | 一段关闭滤镜样本 CPU 较低，同时捕获数量和桌面负载也变化 | 无法把全部差额归因于 shader |
| 纹理池试验 | 复用三张共享纹理后出现计数停滞和程序无响应，已撤回 | 该复用实现不可靠，具体根因未确定 |
| profile 崩溃 | 原版对照和候选版均在 flutter_windows.dll + 0x8b0bb0 访问违规；本机 PDB 定位到 Dart ProfilerNativeStackWalker | 崩溃位置不能单独证明根因；关闭命令行采样选项后仍复现 |
| 最终呈现 | WPR GPU/DesktopComposition 跟踪启动被策略/权限拒绝 | 尚未取得逐帧上屏时间，不能确认一两帧延迟具体位于最终哪一级 |

用户实测：小窗静止时动态背景也会卡；后续版本有明显改善，但仍有一两帧延迟，拖动仍卡。这些反馈决定当前未通过验收。

## 源码中的设计问题

1. `windows/runner/flutter_window.cpp` 的 `UpdateMiniDrag` 直接移动窗口，背景通过另一条异步路径更新，二者没有同步呈现协议。晚裁剪只能缩短坐标过期时间。
2. `RenderGpuFrame` 逐帧创建共享纹理并返回新句柄；Flutter Windows 外部纹理对变化的句柄重新导入 EGL 表面。只量裁剪无法覆盖该成本。
3. FlutterDesktopGpuSurfaceDescriptor 的 release_callback 表示句柄已被 Flutter 打开，**不表示 GPU 已完成采样**。不能将它当作覆盖纹理的完成栅栏。macOS CVPixelBufferPool 的回收语义不能直接照搬到 Windows。
4. 当前仍保存整屏快照，区域外更新也可能触发小窗工作。保存最新桌面与重绘小窗需要分开。更新区域诊断未完成，尚无浪费比例结论。
5. 捕获按窗口所在显示器选择设备，尚未核对 Flutter 渲染适配器；Intel/NVIDIA 双适配器环境需要明确的共享资源兼容或回退路径。
6. Windows 仍用历史 frames 推断有效帧。捕获设备重建时应明确当前帧失效和恢复条件，不能把旧帧当作恢复完成。

## macOS 可以复用的原则

`packages/desktop_glass/macos/Classes/DesktopGlassPlugin.swift` 保存最新整屏，取纹理时才裁剪；桌面版本与位置共同决定缓存是否有效；合并通知；低频统计不驱动画面。

Windows 已尝试晚裁剪、移动通知和等待新帧。尚需解决 Windows 资源生命周期、消费者完成同步、跨适配器兼容和最终呈现时序，不能用捕获帧率或编译成功替代。
